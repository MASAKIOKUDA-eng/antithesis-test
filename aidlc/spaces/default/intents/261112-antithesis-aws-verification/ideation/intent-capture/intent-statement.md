# Intent Statement

## 一文で
Antithesis（決定論的シミュレーションテスト基盤）を導入する前に、
**「テストの形」を無料で作って AWS 上で回し、そのまま Antithesis 本番起動へ切り替えられる検証環境**を IaC（AWS CDK、cdkd でデプロイ）で用意する。

## 背景
- Antithesis は有償（PoC / Teams プラン月額 2,999 ドル）で、本体は OSS ではない。
- 一方 SDK・Docker Compose 構成・Test Composer コマンドは手元で作れる。
  解説資料の「検証を進める順番」:
  1. 無料: Compose 構成 + SDK アサーション + driver を用意し動作確認
  2. バグを仕込んだブランチを作り、評価の物差しにする
  3. Teams / PoC で、仕込んだバグが見つかるか・再現性・デバッグのしやすさを評価

## 成功の定義
- ステップ 1・2 が **契約なしで** AWS 上（CodeBuild）で自動実行できる
- 「正しい実装は pass、仕込んだバグは fail」と機械判定できる
- 契約後は **設定値 1 つ（`antithesisEnabled=true`）＋ シークレット投入** だけでステップ 3 に移れる
- 脆弱性対策を最優先（認証情報をコード・Git・ログに残さない、最小権限、暗号化、cdk-nag で常時検査）

## 利害関係者
| 役割 | 関心 |
| --- | --- |
| 検証担当（依頼者） | 早く・安く・再現可能に Antithesis を評価したい |
| セキュリティ担当 | 認証情報の扱い、外部（Antithesis）へ出すコード・データの範囲 |
| Antithesis（外部） | 指定形式のイメージと起動 API 呼び出し |
